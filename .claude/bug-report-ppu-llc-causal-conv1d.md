# Bug Report: ppu-llc SIGABRT on causal_conv1d_update_with_batch_gather kernel (float32)

## Summary

`ppu-llc` (SDK v2.1.1) crashes with SIGABRT (exit code 134) when compiling a Triton kernel generated by `causal_conv1d_update_with_batch_gather` in float32 mode. This is a regression from SDK v2.1.0 where the same test passes.

## Environment

| Component | Version |
|-----------|---------|
| PPU SDK | 2.1.1-a5c56e |
| ppu-llc | LLVM 13.0.1, ppu version 2.1.1-a5c56e |
| Docker Image | `pkg.flytiger-eco.com/docker_release/llm:v2.1.1-pytorch2.11.0-ubuntu24.04-cuda13.0-sglang0.5.13-py312` |
| Triton | 3.6.0 |
| PyTorch | 2.11.0 |
| Python | 3.12.3 |
| Driver | 1.6.1-8deb0c |
| VBIOS | 1.6.12-af69f0 |
| Hardware | PPU 810E (16 cards) |

## Reproducer

```bash
# Inside the Docker container:
cd /path/to/sglang-for-sail/test
python3 -m pytest "registered/layers/mamba/test_causal_conv1d.py::test_causal_conv1d_update_with_batch_gather[3-True-2064-3-1-False-False-itype0]" -v
```

The test calls `causal_conv1d_update` from `sgl-kernel` with `dtype=torch.float32`, `dim=2064`, `width=3`, `has_batch_indices=True`, triggering a Triton kernel compilation that crashes `ppu-llc`.

## Error Output

```
RuntimeError: ppu-llc error: `/usr/local/PPU_SDK/bin/ppu-llc -lineinfo \
  --ppu-backend-options --ppu-blksync-schedule-boundary=false \
  --ppu-backend-options --ppu-enable-rewrite-partial-reg-uses=true \
  --ppu-backend-options --ppu-max-vreg-count=256 \
  --ppu-backend-options --max-analysis-recursion-depth=7 \
  --ppu-backend-options --enable-threadIdx-x-div32-always-uniform=true \
  -v --gpu-name=sm_80 /tmp/tmp9m62g8it.tix.trans -o /tmp/tmp9m62g8it.tix.trans.o` \
  failed with return code 134
```

Return code 134 = SIGABRT (likely an internal assertion failure in ppu-llc).

## Scope of Impact

- **Only `itype0` (float32) fails** — `itype1` (float16) and `itype2` (bfloat16) pass fine
- **Only `test_causal_conv1d_update_with_batch_gather` fails** — all 12 `test_causal_conv1d_update` (without batch_gather) pass
- The combination of float32 + batch_gather code path generates IR that triggers the ppu-llc crash

## Workaround

Currently disabled in CI with:
```python
register_ppu_ci(
    est_time=11, suite="nightly-1-ppu", nightly=True,
    disabled="ppu-llc SIGABRT on causal_conv1d_update_with_batch_gather itype0 (float32); SDK 2.1.1 bug"
)
```

## Suggested Investigation

The `.tix.trans` intermediate IR file is generated to `/tmp/` during compilation. To capture it for offline debugging:
```bash
export TRITON_CACHE_DIR=/tmp/triton_debug
# Run the failing test — the .tix.trans file will be preserved in the cache dir
```

The crash is likely in the ppu-llc backend's register allocation or scheduling pass, triggered by a specific IR pattern from the float32 batch_gather kernel (wider registers than fp16/bf16).
